# Authentication and Authorization

Understanding the difference between authentication (authN) and authorization (authZ) is fundamental for building secure systems.

## Authentication vs Authorization

### Authentication (AuthN): "Who are you?"
- Verifying user identity
- Methods: passwords, biometrics, tokens

### Authorization (AuthZ): "What can you do?"
- Checking permissions
- Methods: RBAC, ABAC, OAuth scopes

### 2. OAuth 2.0

Four grant types:

#### Authorization Code Grant (Recommended for Web Apps)

```python
# Step 1: User authorizes
GET https://auth.example.com/oauth/authorize?
    client_id=YOUR_CLIENT_ID&
    redirect_uri=https://yourapp.com/callback&
    response_type=code&
    scope=read+write

# Step 2: Exchange code for token
POST https://auth.example.com/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&
client_id=YOUR_CLIENT_ID&
client_secret=YOUR_CLIENT_SECRET&
code=AUTHORIZATION_CODE&
redirect_uri=https://yourapp.com/callback

# Response
{
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "Bearer",
    "expires_in": 3600,
    "refresh_token": "dGhlIHNlcHFld..."
}
```

#### Client Credentials Grant (For Server-to-Server)

```python
POST https://auth.example.com/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&
client_id=YOUR_CLIENT_ID&
client_secret=YOUR_CLIENT_SECRET

# Response
{
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "Bearer",
    "expires_in": 3600
}
```

#### Implicit Grant (For SPAs - Deprecated)

```python
# Redirect user to auth server
GET https://auth.example.com/oauth/authorize?
    response_type=token&
    client_id=YOUR_CLIENT_ID&
    redirect_uri=https://yourapp.com/auth&
    scope=read

# After authorization, access token in URL fragment
https://yourapp.com/auth#access_token=eyJhbGci...
```

#### Resource Owner Password Credentials (Least Secure)

```python
POST https://auth.example.com/oauth/token
Content-Type: application/x-www-form-urlencoded

grant_type=password&
client_id=YOUR_CLIENT_ID&
client_secret=YOUR_CLIENT_SECRET&
username=user@example.com&
password=user_password
```

### 5. OAuth 2.0 with PKCE

```python
# PKCE adds a code verifier and challenge for better security
import secrets

def generate_pkce_codes():
    # Generate a random code verifier (43-128 characters)
    code_verifier = secrets.token_urlsafe(16)

    # Create code challenge (SHA256 of verifier)
    code_challenge = base64_url_encode(sha256(code_verifier))

    return code_verifier, code_challenge

# Step 1: Register PKCE with auth server
GET https://auth.example.com/oauth/authorize?
    response_type=code&
    client_id=YOUR_CLIENT_ID&
    code_challenge=YOUR_CODE_CHALLENGE&
    code_challenge_method=S256
    ...

# Step 2: Exchange code for token with PKCE
POST https://auth.example.com/oauth/token
grant_type=authorization_code&
code=AUTH_CODE&
code_verifier=YOUR_CODE_VERIFIER
```

## Authorization Models

### 1. RBAC (Role-Based Access Control)

```python
# Role definitions
roles = {
    "admin": {
        "permissions": [
            "users:read",
            "users:write",
            "users:delete",
            "posts:read",
            "posts:write"
        ]
    },
    "editor": {
        "permissions": [
            "posts:read",
            "posts:write"
        ]
    },
    "viewer": {
        "permissions": [
            "posts:read"
        ]
    }
}

# User assignments
users = {
    "alice": {"role": "admin"},
    "bob": {"role": "editor"}
}

# Check access
def check_access(user, resource, action):
    user = find_user(user_id)
    permission = f"{resource}:{action}"
    return permission in user.role.permissions
```

### 2. ABAC (Attribute-Based Access Control)

```python
# Attribute definitions
attributes = {
    "users": {
        "id": "string",
        "name": "string",
        "department": "string"
    },
    "posts": {
        "id": "string",
        "author_id": "string",
        "sensitivity": ["public", "internal", "confidential"]
    }
}

# Policy evaluation
def can_access(user, post):
    # User must own the post
    if post.author_id != user.id:
        return False

    # Or user is admin
    if is_admin(user):
        return True

    # Or post is public
    if post.sensitivity == "public":
        return True

    return False
```

### 3. Policy-Based Access Control

```python
# Centralized policies
policies = {
    "GET /api/users": ["admin", "hr_manager"],
    "POST /api/users": ["admin"],
    "GET /api/posts": ["all"],
    "POST /api/posts": ["admin", "editor"],
    "GET /api/admin/settings": ["admin"]
}
```

## OAuth Flow Implementation

### Complete OAuth 2.0 with Authorization Code Flow

```python
# 1. Register OAuth Client
class OAuthClientRegistration:
    def __init__(self, redirect_uri: str, scopes: list):
        self.client_id = self._generate_client_id()
        self.client_secret = self._generate_client_secret()
        self.redirect_uri = redirect_uri
        self.scopes = scopes
        self.client_type = "confidential" if self.is_confidential else "public"

    def create(self, auth_server: AuthServer):
        response = auth_server.register_client({
            "redirect_uri": self.redirect_uri,
            "scope": " ".join(self.scopes)
        })
        return response

# 2. Authorization Endpoint
def authorize_user(redirect_uri: str, scopes: list):
    auth_url = f"{AUTH_SERVER_URL}/oauth/authorize"
    params = {
        "client_id": self.client_id,
        "redirect_uri": redirect_uri,
        "response_type": "code",
        "scope": " ".join(scopes),
        "state": self._generate_state()  # CSRF protection
    }
    return auth_url + "?" + urlencode(params)

# 3. Token Exchange
def exchange_token(code: str, state: str):
    if self._validate_state(state):  # CSRF check
        token_data = {
            "grant_type": "authorization_code",
            "code": code,
            "redirect_uri": self.redirect_uri,
            "client_id": self.client_id,
            "client_secret": self.client_secret
        }
        response = requests.post(TOKEN_ENDPOINT, data=token_data)
        return response.json()
```

## JWT Claims

```python
# Header
{
    "alg": "RS256",  # RS256 for RSA, ES256 for EC
    "typ": "JWT"
}

# Payload (Header claims)
{
    "iss": "https://auth.example.com",      # Issuer
    "sub": "1234567890",                    # Subject (user ID)
    "aud": "my-api",                        # Audience
    "exp": 1511564400,                      # Expiration (Unix timestamp)
    "nbf": 1511096400,                      # Not before
    "iat": 1511561000,                     # Issued at

    # Custom claims
    "name": "John Doe",
    "role": "admin",
    "permissions": ["read", "write"]
}

# JWT Structure
header_payload = {
    "header": {
        "alg": "HS256"
    },
    "body": {
        "sub": "1234567890",
        "name": "John Doe",
        "iat": 1511561000
    },
    "signature": "Signature"
}
```

## Refresh Token Rotation

```python
# Create refresh token pair
refresh_token = RefreshToken()
new_refresh_token = RefreshToken()
access_token = create_access_token(refresh_token)

def handle_refresh_token_request():
    request_token = request.json["refresh_token"]

    # Validate and check expiration
    if not refresh_token.validate() or refresh_token.is_expired:
        raise InvalidRefreshTokenError()

    # Revoke old token
    refresh_token.revoke()

    # Create new token pair
    new_refresh_token.create()
    new_access_token = create_access_token(new_refresh_token)

    return jsonify({
        "access_token": new_access_token,
        "refresh_token": new_refresh_token.value
    })
```

## Security Best Practices

1. **HTTPS Only**: Always use HTTPS for token transmission
2. **Short-lived Access Tokens**: 15-60 minutes
3. **HttpOnly Cookies**: For storing cookies (not JavaScript)
4. **Secure Flag**: Prevents XSS attacks
5. **SameSite Attribute**: Prevent CSRF attacks
6. **Token Refresh**: Implement refresh token mechanism
7. **Token Revocation**: Ability to revoke tokens
8. **Rate Limiting**: Prevent brute force attacks
9. **Logging**: Log authentication failures
10. **Monitoring**: Monitor unusual authentication patterns
